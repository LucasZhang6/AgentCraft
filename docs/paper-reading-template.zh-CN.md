# 论文条目规范

[English](paper-reading-template.md) | [简体中文](paper-reading-template.zh-CN.md)

这份规范用于保持站内论文条目一致、清晰和可验证。条目应区分论文事实、作者主张与项目维护者的工程推断。

## 基本信息

- 标题：
- 作者与机构：
- 发表时间与会议：
- 原文链接：
- 官方代码或项目页：
- 所属模块：LLM / Loop / Memory / Tool / Planning / Evaluation / Safety / RL / Engineering

## 论文概要

用 80 至 150 字回答三个问题：论文研究什么问题、使用什么核心方法、最重要的价值是什么。概要应能独立阅读，避免堆叠术语，也不要写“效果显著”而不指出效果是什么。

## 详细解读

详解不少于 200 字，并按以下角度展开。先解释论文事实和作者结论，再给出项目维护者的工程判断；两者不能混写。

### 问题背景

先描述没有这项方法时，系统具体会在哪里失败。必要时给出 Agent 任务例子，明确研究问题的实际边界。

### 核心方法

解释输入、关键状态、决策过程和输出。遇到公式时，先解释每个变量在系统中的含义，再说明优化目标。不要用一串论文术语代替解释。

### 实验与证据

列出数据集或环境、主要基线、核心指标和最重要结果。区分论文明确证明的结论与作者推测。检查是否有消融实验、成本报告和失败案例。

### 对 Agent 的意义

指出它改变 Controller、Memory、Tool、Planner、Evaluator、Logger 或 Skill Library 中的哪个部分。说明收益，也说明新增的成本和攻击面。

### 工程落地

给出一个一至两天能完成的最小实验，明确输入、输出、验收指标和对照组。不要只写“可以用于专属 Agent”。

### 局限与开放问题

至少写三项：适用边界、评估缺口、规模或成本问题、安全风险、复现难点。最后给出你自己的判断，并标明它是推断而非论文结论。
